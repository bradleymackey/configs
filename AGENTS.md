# AGENTS.md

Personal dotfiles and machine setup for macOS (Apple Silicon). Configs live in `home/` and are
symlinked into `$HOME` by a Bun/TypeScript installer in `install/`. User docs: `README.md`;
installer design: `INSTALLATION.md`; module API and rules: `install/README.md`.

## Commands

```bash
bun run test        # hermetic suite + coverage gate (>= 95% lines/functions per file)
bun run typecheck   # tsc --noEmit
bun run dry-run     # preview every setup step on this machine (safe: nothing mutates)
bun run verify      # symlink + environment check, read-only
bun run setup       # the real install; only run when asked
bun test test/unit/brew.test.ts   # single file
```

Run `test`, `typecheck`, `dry-run` and `verify` before committing installer changes.

## Target: a brand-new Mac

`bun run setup` must work on a fresh Mac, which differs from the dev machine in ways the hermetic
tests cannot see:

- **Default shell is zsh.** Setup is launched from zsh, so nothing from `.bashrc` is in the
  environment (`PNPM_HOME`, the Homebrew/cargo/pnpm `PATH` entries). A step that needs a
  variable must set it on `ctx.env` itself (see `ensurePnpmHome` in `install/node.ts`, and
  the `PATH` updates after installing Homebrew and rustup).
- **The login shell must become `/bin/bash`** (macOS system bash, 3.2). `setupLoginShell` in
  `install/macos/macos.ts` runs `chsh`. Keep `.bashrc` / `.bash_profile` working on bash 3.2.
- **No Homebrew, no Command Line Tools, no SSH key, no `~/.profile`.** Submodule URLs in
  `.gitmodules` must be `https://` (enforced by `test/repo/hygiene.test.ts`); rc files must
  guard optional sources (`[ -f ~/.profile ] && source ~/.profile`).
- **Prompts need a TTY.** The runner gives commands `stdin: "ignore"` by default. Anything that
  asks for a password or confirmation must pass `interactive: true`, and usually `stream: true`
  so the prompt is visible. The Homebrew installer checks `[ -t 0 ]`; without a TTY it switches to
  non-interactive mode, uses `sudo -n`, and aborts with "Need sudo access". `chsh` needs one too.
- **Installers must never edit rc files.** `~/.bashrc` and `~/.bash_profile` are symlinks into
  this repo, so any tool that appends to them dirties the repo. rustup runs with
  `--no-modify-path`; fzf's install script runs with `--no-update-rc --no-zsh --no-fish
  --no-nushell`. `.bashrc` already sets up `PATH` for them.
- **Check the file the config actually uses.** fzf's formula always ships
  `opt/fzf/shell/key-bindings.bash`; what `.bashrc` sources is `~/.fzf.bash`, generated by fzf's
  install script. Both `brew.ts` and `verify.ts` key off `~/.fzf.bash`.
- Before relying on an external installer's behaviour, confirm it against upstream, e.g.
  `curl -fsSL https://raw.githubusercontent.com/Homebrew/install/HEAD/install.sh | rg 'not a TTY'`.

Fresh-Mac bootstrap order and the manual follow-up steps (SSH key, secrets, log out and back in)
are in the "New Mac" section of `README.md`. Keep them in sync with the installer.

## Installer rules (`install/`)

- Run every command through `ctx.runner.run(cmd, { mutates })` and declare `mutates`
  honestly: the dry-run runner only reports mutating commands, but it still executes read-only
  probes so the preview reflects the real machine.
- Filesystem changes go through `install/lib/fs-ops.ts` (lstat + `symlinkSync`, with a backup
  of anything replaced) or check `ctx.dryRun`. In dry-run, report changes with status `"planned"`.
- Never read or write `process.env` inside a step; use `ctx.env`.
- Guard entry points with `if (import.meta.main)` and use `runStandalone`, so every step also
  runs on its own with the same flags.
- The symlink manifest is `install/symlinks.ts`. Every tracked entry in `home/` must be linked
  there or listed in `UNLINKED_ENTRIES`.
- Tools that `verify` requires (`REQUIRED_TOOLS`) must have their `brew:` provider in
  `home/Brewfile`, and every third-party formula must be tapped (hygiene tests enforce both).
- Never name a `package.json` script `install` or another lifecycle name: `bun install` would
  run the installer.
- Code style: descriptive names, async/await, helpful error messages, coloured
  `[INFO]/[SUCCESS]/[WARN]/[ERROR]` output via `ctx.log`; failed steps report and continue
  rather than throw.

## Tests (`test/`)

- No test may touch the real HOME, the real repo tree, or a real package manager. Use `makeCtx`,
  `FakeRunner` (records `cmd` and `opts`), `makeFixtureRoot` and `tempDir` from `test/helpers.ts`.
- Test every step in both normal and dry-run mode, including "no mutating command ran".
- `test/integration/dry-run-safety.test.ts` runs the real CLI with stub binaries on `PATH`. A new
  external command needs a stub there, and a new read-only probe needs a `READ_ONLY` pattern.
- `test/env/` is opt-in (`bun run test:env`) and read-only against this machine.

## Shell and configs

- Bash only: no zsh configuration. `grep` is aliased to `rg`; prefer `rg` in scripts and docs.
- Secrets never go in the repo. `.bashrc` sources `~/.bash_secrets` if present (gitignored);
  `~/.profile` is untracked. Both are copied to a new machine by hand.

## Git

- Conventional commits with a scope where it helps: `feat(install): …`, `fix(config): …`,
  `docs: …`, `test: …`, `chore(brew): …`, `build: …`.
- Submodules: `home/.config/base16-shell`, `home/.config/swift_po`.
